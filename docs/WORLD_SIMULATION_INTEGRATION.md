# World / simulation integration findings

Reviewed on 2026-11-15: collaborator PR #3 (`feat/world-construction`, `e44be98`) combined with A1/A2 (`00e3f00`). The integration branch preserves contributor commits and leaves the original PRs open for review. No shared contract or science values were changed.

The original combined baseline passed WORLD 679, INTEGRATION 44, A1 14289 and A2 41144 checks and headless scene boot. PR #3's own GitHub tests/exports also passed. Those successes did not establish a complete game: the authored map explicitly selected a visual stub and several bridge failure paths were untested.

## Reproduced defects and fixes

| Trigger | Observed failure | Integrated behavior |
|---|---|---|
| Mutate a bridge snapshot or its signal payload | The cached presentation view changes without a simulation commit | Reads and emitted snapshots are detached copies |
| Keep a backend reference, switch worlds, then emit from the old backend | Retired snapshot/result/event signals still reach the current world | Disconnect all three named signal handlers before replacement |
| Select authored map/definitions with fixture initialization config | Boot reports success while simulation and rendered content disagree | Validate manifest paths/hashes, map identity/revision and building references before attaching |
| Break a simulation config with AUTO selected | Startup silently becomes a successful resource-free stub | A present simulation must initialize successfully; stub use is explicit or script-absence development fallback |
| Switch presets repeatedly | Each setup adds another cursor and ghost root | Reuse the two existing preview roots |
| Fail a tick during frame advancement | The return value is ignored and failing time is retried each frame | Stop automatic advancement, emit one error and show the last committed state with a restart explanation |
| Resolve a placement synchronously | A resolution message can be overwritten by a stale submission message | Preserve the resolved outcome |
| CI import returns an error; A2 is present | Import failure is ignored and A2 has no CI step | Fail on exit/error text and run all available suites, A2, bridge regressions, benchmarks and fixture checks |

The bridge regression runner was executed before fixes and produced six failing assertions (aliases, retired backend, mismatched world, hidden fallback, leaking roots). After fixes it passes 17 checks, including failure injection and failed-load isolation. World integration now passes 52 checks; the world service and A1/A2 suites retain their original acceptance results.

## What now runs together

Both presets boot `OutpostSimulation` through the bridge. The authored scenario is an explicitly synthetic fixture generated by `tests/world/tools/generate_integration_scenario.py`. It includes seven commissioned modules from the collaborator's demo and omits its unfinished greenhouse/task, which cannot yet be represented through runtime initialization. The visual construction stub remains isolated for world-service and screenshot tests.

On the authored map, two solar arrays generate `3 + 3 * 0.82 = 5.46 kW`. Loads request `0.8 + 1.5 + 0.6 = 2.9 kW`. The battery starts with 14/20 kWh. The first tick gains `(5.46 - 2.9) / 3600 * 0.95 kWh`; after both solar arrays are disabled, a fully served tick consumes `2.9 / 3600 / 0.95 kWh`. Tests verify these against the actual bridge snapshots. Oxygen remains unchanged because served electricity is not life-support production.

The real Windows game window was opened and inspected: authored terrain/modules rendered, `F3` selected the authored simulation, the overlay showed live power/battery values, `Space` paused at a fixed tick, and a valid placement click displayed the explicit `module_unavailable` rejection. The window was closed after testing. WASAPI could not open the machine's current audio output and Godot fell back to its dummy driver; this is an observed environment limitation, not evidence of game sound working.

## Remaining game failures / incomplete features

- Construction previews work, but real placement is rejected until Task 01/03 implement spending, construction templates, labor and commissioning. The visual stub's free placement is not integrated gameplay.
- Life support, metabolism, agriculture and environmental hazards are pending. Powered equipment does not generate oxygen or water, remove CO2, or keep crew alive yet.
- Crew models/HUD, assignment, EVA travel/work/recall and salvage transfer lifecycle remain Task 03 integration work. Route previews alone do not execute expeditions.
- Save/load remains explicitly unavailable. `F2`/`F3` resets colony state; switching maps does not preserve progress.
- Authored balance parameters, fixture crew/science, and procedural terrain are synthetic placeholders. No NASA elevation asset or source-backed physiology/equipment values were adopted.
- The developer overlay and camera are a prototype presentation, not a finished tutorial/player interface. Audio was not validated on functioning hardware.

Deep research would help establish A3 physiology, atmosphere and equipment parameters before real science is adopted, as already flagged under AGENTS.md. This integration did not undertake that research.

## Reproduce

```powershell
python tests/world/tools/generate_integration_scenario.py --check
python tests/simulation/tools/generate_fixtures.py --check
python tests/simulation/tools/closed_form_checks.py
```

For the graphical check, run `<godot-console> --path .`, press `F3` for the authored map, and `Space` to pause. Use number keys to preview a module and click a valid cell to see the current construction rejection. Full test/CI results cover the synthetic scenario; they do not certify unimplemented gameplay or production scientific fidelity.
